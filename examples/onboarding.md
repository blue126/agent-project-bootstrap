# 从这里开始：先准备本地 Agent coding 项目

Bootstrap 的目标是让你获得客户端适配、工作方法、Skills、项目规则和本地 Git。它不会自动开始开发、提交代码或接入整套 GitHub 治理。本仓库是分发源码，看到目录不等于组件已安装到你的项目。

## 一个入口

第一次从 GitHub 来到这里，还没有工具 checkout？先按 [README 快速开始](../README.zh-CN.md#快速开始初始化项目) 获取工具并进入自己的项目目录。工具仓库和目标项目是两个目录，不要在下载的工具仓库里误做初始化。

如果工具按 README 放在主目录，在 Terminal.app、iTerm 等普通终端进入**目标项目根目录**后运行：

```bash
"$HOME/agent-project-bootstrap/scripts/bootstrap.sh"
```

默认目标就是当前目录，不必写 `--target "$PWD"`。先核对开场显示的实际项目路径再开始；只有要操作其他目录时才用 `--target DIR`。工具放在别处时，只调整启动脚本路径。

不要让 Agent 开工具 PTY 代跑真实安装器，也不要清除 Agent 检测变量绕过限制。开场 `i` 查看各阶段的“检查 / 可能改变 / 不会”，Enter 返回。只看说明或退出，不会创建不存在的目标目录。

客户端和工作方式用方向键选择，客户端可用空格多选，Enter 确认。`TERM=dumb` 时按提示输入编号或 ID，客户端可输入多个。取消不会隐式接受默认项；新客户端选择每次都需要确认。原生 Skills 安装器继续使用它自己的搜索、多选、安装进度与确认界面。

## 五个基础阶段

### 1. 选择 Agent 客户端

选择 Claude Code、Codex、OpenCode、Universal，可多选。检测到的项目入口或已有 `project_agents` 只作为预选，不替你决定。

Universal 表示 `.agents/skills` 共享目录兼容模式，不是一个客户端应用，也不是“安装全部”。选择客户端不会自动安装或登录应用。后续原生 Skills 调用复用明确的 `--agent` 目标，不再靠自动检测选择客户端。

### 2. 选择工作方式

- **github-workflow**：本地分支、审阅、提交以及之后可选的 GitHub 协作。
- **Superpowers**：功能设计、计划、实现与验证。
- **BMAD**：需求、架构与系统性迭代。
- **保留现有方法**：不新增框架，仍可获得基础规则、Skills 和 Git。

已有 active 配置保留；没有明确采用配置时，选择“保留现有启用状态”不会激活检测到的框架。明确选择“采用”会在之后确认基础配置时保存，仍不执行任务。多个已安装框架不取检测结果的第一个自动激活。

BMAD 6.12.0 没有 Universal tool ID。Claude Code、Codex、OpenCode 的输出路径不同，尤其 OpenCode 还需要 command pointers；不支持的组合会说明，不能因为共享目录存在就声称兼容。

### 3. Skills 与可选能力

先安装选定工作流缺失的内容，再独立选择普通 Skills。**已有 Skill 或刚装完工作流，也始终可以继续添加普通 Skills。** 为新客户端复用已有项目 Skills 时，先展示缺失入口的相对链接建议，确认后仅补链接，不更新原内容；冲突保留。

官方界面仍可能在不同安装调用中分别询问 scope 和 method，推荐 Project。当前固定 CLI 的 `add` 没有 `--project` 参数，不使用 `-y` 或 `--all` 强行消除提问。选择 Global 只代表原生安装器中的作用域选择，不证明项目目录中已有入口。

Understand Anything 是可选能力：已有代码库（brownfield）更适合用它理解结构，空项目（greenfield）可以跳过。安装固定版本到 `.agent/runtime`，保留共享 canonical 链接，并为所选 Claude 客户端补入口；已有 runtime 也可以补缺失入口。不装全局插件，不自动分析；后续分析可能产生模型费用。

### 4. 项目规范与本地 Git

确认必要的客户端/工作流项目偏好和政策；已有指令不覆盖。`.agent/policies/git.md` 通过项目 Agent 入口引用，指导后续初始化、暂存、提交和清理。

- 共享 Skills、hooks、配置、锁文件、BMad 正式研究/需求/设计是待审阅的项目资产，不因隐藏或生成属性排除。
- 个人覆盖、凭据、运行状态、缓存、worktree 留在本机。
- `.gitignore` 缺少时生成最小规则；已有原文只做确认过的追加合并。宽泛规则遮蔽资产时报告，不自动删除。
- 旧 Skills 整目录忽略的迁移另行确认，`--update --force` 也不会悄悄打开旧边界。
- 本地 Git 可以独立初始化，不依赖 GitHub；已有分支、origin、暂存内容都保留，不设置全局身份。

拒绝基础配置写入时，本次客户端选择不会成为新的持久记录。缺少必要配置则报告待处理，不伪装就绪。

### 5. 本地结果与开始工作

结果列出项目客户端、工作方式、实际入口数量、规则和 Git 状态，并给出所选工作流的起步方式。

“本地配置就绪”不等于“客户端已加载”：在所选客户端的新会话打开项目，先让 Agent 说明它实际读取到的规则和能力，再授权第一个任务。没有初始提交会明确显示“尚未提交”，首次提交前仍需审阅资产、敏感信息、大文件和符号链接。

空项目没有业务测试或 CI，不妨碍基础流程正常结束；也不会生成一个永远成功的占位验证器。

## GitHub 是可选续程

本地总结之后才询问是否继续 GitHub。选择不继续即正常结束，不再逐项询问 CI、Review 和 Rulesets。即使项目有 GitHub origin，选择继续之前也不访问远端。

继续时可以创建或连接明确的仓库，依旧不暂存、不提交、不推送。仓库名称是必填的 `OWNER/REPOSITORY`，空输入重试，`b` 返回，`q` 退出。之后的实际发布、CI、自动审查与保护仍需相应授权和真实证据。

本仓库的 `--profile self` 只适用于 `blue126/agent-project-bootstrap/main`，不是下游默认保护。下游采用自身 CI 的真实 evidence，治理敏感操作仍由人工处理。

只有在这个可选续程中明确选择验证协助，才生成 `.agent/runtime/onboarding/validation-handoff.md`。先前本地总结会保留；任务文件不是 resume cursor，也不提供运行、下载或发布授权。

## 重跑与更新

中断、完成外部工作或想增加客户端时，重跑同一条入口命令；它重新检查文件和 Git，不恢复上次做到第几题。项目配置中的 `project_agents` 是可移植偏好，既不是安装证明，也不是持久授权。

仅刷新受管政策用 `--update`，不会重跑安装器或改变客户端选择。`rehydrate.sh` 会复用记录的客户端，能自动重建的 UA 与需要人工完成的 Skills/BMAD 步骤分别报告，不把待办说成恢复完成。更多信息见 [README](../README.zh-CN.md)。
